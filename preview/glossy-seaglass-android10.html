Sea glass on Android 10 — yes, and here is exactly what you get

Short answer: you can see it — but you see a drawn pane, not a frosted one.

The real glass is a RuntimeShader pass that samples what is behind the surface and frosts it. RuntimeShader only exists from API 33 (Android 13). Android 10 is API 29, so seaGlassSurfacesAvailable is false there and every surface falls back to Modifier.seaGlassFallback(): the same pane painted directly — tint inside the body, the highlight thrown back at the light, a chalky rim, the drop shadow and the press scale.

What Android 10 does not get is the refraction: the pane cannot blur or bend what is behind it, so it reads as tinted glass rather than as frosted glass. Flip the switch to see the two side by side.

Drop shadow, press scale, sheenyes — plain Composeyes — plain Compose
Frost / blur of the backdropno — needs RuntimeShaderyes
Refracted or “lensed” edgesnoyes

4 — How the app decides

  • seaGlassSurfacesAvailable = SDK_INT >= TIRAMISU — the one switch, in SeaGlassSupport.kt.
  • False → Modifier.seaGlassFallback(fill, shape): clip, a vertical tint gradient, a top highlight that fades, a bottom bounce, and a 1dp chalky rim.
  • True → the real seaGlass(material, …) pass, which samples the backdrop.
  • Tooling previews take the fallback path on every API level, because a preview has no GPU pass to sample — so what you see in a preview is what Android 10 sees.

5 — If you want it closer to frosted on old devices

There is a way, and it does not need the shader: the project already ships a CPU blur backdrop (BlurredArtworkBackdrop, used by the mini player's blur style and the player background), which is why those work below API 31 where Compose's own Modifier.blur does not exist. The same idea could sit behind a SeaGlassPanel so Android 10 gets a genuinely frosted pane. It costs a bitmap decode and a blur per panel, so it is a real trade — worth doing for the two or three panels on screen, not for every pill.
