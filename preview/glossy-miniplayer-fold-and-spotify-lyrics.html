Mini player fold removed · Spotify lyrics fixed

Two changes, both from the same two reports: a small round pill that was never round, and Spotify lyrics that could never parse.

1The fold into a small round pill is gone

The materialistic redesign made every mini player style fold on scroll: the bar kept its 64dp height while giving up its width until only a fraction of the screen was left, then clipped itself with RoundedCornerShape(percent = 50) and traced a wavy progress ring around the artwork that remained. Percent-50 on a box that is far wider than it is tall is a stadium, not a circle — which is exactly what you saw: it never read as round, and in Legacy it fought the bar's own layout on the way there. Each style now keeps its full width and its own shape for as long as it is on screen.

Valhalla CallingRagal Ironbull
✕Height fixed at 64dp, width cut to 24% of the screen: what is left is roughly 86dp × 64dp, so the clip rounds it into a squat capsule. The 56dp ring does not sit concentric with a shape that has no single centre.
After — full width, always
Valhalla CallingRagal Ironbull
✓Studio, Glossy Special Edition, Modern and Legacy all keep the exact shape their own design draws. No clip, no ring, no animation — and the crash the animation caused can no longer happen, because the shape it built is not built at all.

The Apple Music style is the one exception, and deliberately so: it was the first bar to fold, it folds by re-flowing its own row rather than by clipping, and it is the behaviour its own description documents. Say the word and it goes too.

2Why Spotify lyrics never appeared

The app already had a Spotify provider, already signed in with the same sp_dc cookie SimpMusic uses, and already called the same endpoint — color-lyrics/v2/track/{id} with a bearer token and a client token. It failed one step later, in the parser, because it read a shape that endpoint does not return.

What the parser expected 
{
  "lyrics": {
    "syncedLines": [
      { "startTime": 960,
        "words": [ { "words": "One" },
                   { "words": "two" } ] }
    ]
  }
}
✕syncedLines is absent, so the branch never runs. The fallback reads words as an array, throws on the string it actually gets, and runCatching swallows it. Every lookup ends in “Spotify returned no usable lyrics”.
What the endpoint returns 
{
  "lyrics": {
    "syncType": "LINE_SYNCED",
    "lines": [
      { "startTimeMs": "960",
        "words": "One, two, three, four",
        "syllables": [] }
    ]
  }
}
✓lines is read first, startTimeMs as a string, words as finished text. syncedLines and the array form are still accepted underneath.
Endpoint
spclient.wg.spotify.com/color-lyrics/v2/track/{id}?format=json&market=from_token
Auth
Bearer <token minted from the saved sp_dc cookie> + Client-Token
Track match
SpotifyCanvasProvider.resolveTrackUri(title, artist, …)
Output
[mm:ss.xx]Line — timed LRC
[00:00.96]One, two, three, four
[00:04.12]Calling me home where the old gods stand
✓Timestamps are what the lyric view scrolls and animates against. Unstamped text is now dropped rather than returned, so an answer without timings cannot masquerade as a working one — the animation works because the lines carry times.

3Spotify leads when an account is signed in

Two things stood between a signed-in account and its own lyrics: the provider sat second in the default order, and off until a toggle buried in Content settings was found.

Before
  1. NetEase
  2. Spotify
  3. YouLyPlus
  4. Unison
  5. …

Enabled only by the Settings switch, which defaults to off.

After
  1. Spotify
  2. NetEase
  3. YouLyPlus
  4. Unison
  5. …

Leads by default, and is hoisted to the front of whatever order you arranged while an sp_dc cookie is present. Turning the switch off still turns it off.
