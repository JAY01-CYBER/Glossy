Glossy — what changes on your phone, and what it looks like

Your device is on Android 10 (API 29). SeaGlass's Modifier.seaGlass holds a reference to android.graphics.RuntimeShader — an Android 13 API — inside the inlined method body, so ART fails the entire method the first time it runs, before any SDK_INT guard inside it can help. That is the crash you saw, and it is why the sea glass mini player cannot be made to work below API 33 by any build flag or tier override.

So the app now keeps a real fallback below API 33 (the flat pastel pills you already have) and puts the premium motion where it can run: a bloom that grows out of the mini player as it becomes the full player. Both are gated by the app's single motion switch, so “Reduce animation” turns them off along with everything else.

4 · The original lyrics size, back

You meant the full-screen lyrics, and you were right: the word-by-word lyrics view used to paint every line at a fixed 36sp. When it was changed to honour the Appearance slider, that slider’s default was 24sp — so anyone who never opened it quietly lost a third of their lyrics size. The setting’s default is 36sp again, which is exactly the size that was there before, and the slider still moves away from it in both directions. The mini player’s lyrics strip is untouched — the change I made to it has been undone.

5 · Opening a page — settings, an artist, a playlist

Every page change in the app passes through one NavHost, so this is where the page-open motion lives. A page that is not one of the five tabs now rises into place and grows the last few percent, instead of sharing the sideways slide that tab switches use — so opening Settings, an artist, a playlist or an album reads as a page arriving over the one you were on. That page, in turn, recedes: it dims and shrinks slightly rather than sliding away, and closing the detail sinks it back down the way it came.

Reduce animation turns all of it off. With the switch on (or Android’s own “Remove animations” set in developer options) each of the four transitions returns EnterTransition.None / ExitTransition.None, so pages simply appear. Both feed the same rememberAmbientMotionEnabled() that the mini player’s decorations and the player’s opening bloom already read, so there is one answer to “may this app move” rather than several that can disagree.
The settings and queue screens themselves are unchanged: this is about the page that arrives, not about how a page is laid out.
