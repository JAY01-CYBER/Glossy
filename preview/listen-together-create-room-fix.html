Listen Together · "Creating room…" that never finished

A room was never created, and the app never said why: the server refuses to host for this client, the client reported the refusal, and the Listen Together screen had no branch for it. The fix is the missing branch — plus the states around it.

Fix preview Reproduced against the live default server Kotlin only · no APK built

→create_room{ username: "Probe" }
←error{ code: "host_not_allowed", message: "Only allowlisted clients can host rooms" }

Hosting on the app's default server is allowlisted, so no client can open a room there — the room code never arrives. The bundled metroserver/metro_server.py does permit hosting: it passes its own end-to-end suite (37/37, including create_room).

…and then nothing. No spinner, no error, no room code. The sheet goes back to looking idle while the client has already been told the room was refused.
  • One swallowed event. ServerError was collected and every branch except join-rejected fell through to else -> {}.
  • Dead state. isCreatingRoom was written on tap and cleared on success — but never passed to the UI, so it drew nothing.
  • Stale watchdog. A server answer did not cancel the 12 s "no answer" timer, so a rejection could be followed by a bogus timeout message.

! This server is not accepting new rooms. Pick a different server under Settings → Integrations → Listen Together, or host your own.
  • Every terminal outcome clears the pending state and shows the reason: server errors, connection failures, and a rejected join.
  • host_not_allowed gets its own sentence with the settings path, instead of the operator wording "Only allowlisted clients can host rooms".
  • The waiting state is real now — the same progress row the join flow already had.
  • The watchdog is cancelled as soon as the server answers, so one refusal produces one message.
  • Same treatment in the player sheet, which hosts the other Create room button.

How to host your own

  • Run python metroserver/metro_server.py --print-urls — stdlib only, Python 3.11+.
  • Paste the printed address (ws://<lan-ip>:8080/ws) into Settings → Integrations → Listen Together → Server URL.
  • An address typed without a scheme (192.168.1.24:8080) is now normalised to ws://… instead of reaching OkHttp and throwing out of the tap handler.
